# DSA Preparation Roadmap

A structured 120-day preparation plan based on the **DSA Learning Roadmap 2026**. The plan progresses from programming fundamentals to advanced data structures, graph algorithms, dynamic programming, problem-solving patterns, interview preparation, and competitive programming.

The objective is not only to learn individual data structures and algorithms, but to develop the ability to:

**Understand → Implement → Analyze → Recognize Patterns → Solve → Optimize → Explain**

---

# Daily study system

Each study day should follow a consistent structure.

| Activity | Suggested time | Purpose |
|---|---:|---|
| Concept learning | 45–60 min | Understand the topic |
| Implementation | 45–60 min | Write the data structure or algorithm yourself |
| Easy problems | 30–45 min | Build confidence |
| Medium problems | 45–90 min | Develop problem-solving ability |
| Review | 20–30 min | Retain concepts |
| Notes | 10–20 min | Record patterns and mistakes |

A normal study day can take approximately **3–5 hours**.

If less time is available, reduce the number of problems rather than skipping implementation and review.

---

# Problem-solving rules

For every problem, follow this sequence:

1. Read the problem carefully.
2. Identify the input and output.
3. Write down the constraints.
4. Create a simple brute-force solution.
5. Determine its time complexity.
6. Identify the bottleneck.
7. Look for a better approach.
8. Identify the relevant data structure, algorithm, or pattern.
9. Implement the optimized solution.
10. Test edge cases.
11. Explain the solution without looking at the code.
12. Record the pattern used.
13. Record the mistake if the solution failed.
14. Revisit the problem later without looking at the previous solution.

Do not measure progress only by the number of problems solved.

Track:

- Problems attempted
- Problems solved independently
- Problems solved with hints
- Problems requiring a complete solution review
- Repeated mistakes
- Patterns recognized
- Time complexity understood
- Space complexity understood
- Problems successfully re-solved later

# Complexity reference

| Complexity | Typical example |
|---|---|
| O(1) | Array index access |
| O(log n) | Binary search |
| O(n) | Array traversal |
| O(n log n) | Efficient comparison sorting |
| O(n²) | Nested pair comparisons |
| O(n³) | Three nested loops |
| O(2ⁿ) | Many subset/backtracking problems |
| O(n!) | Permutation generation |

Always ask:

```text
Can this solution be made faster?
Can this solution use less memory?
Is the additional memory worth the time improvement?
```

# Pattern recognition reference

When reading a problem, look for clues.

| Problem characteristic | Possible technique |
|---|---|
| Sorted array + pair | Two pointers |
| Continuous range | Sliding window |
| Repeated range sum | Prefix sum |
| Need fast membership | Hash set |
| Need frequency | Hash map |
| Search in sorted space | Binary search |
| Search for minimum feasible answer | Binary search on answer |
| Next greater/smaller | Monotonic stack |
| Top K | Heap |
| Shortest unweighted path | BFS |
| Explore all graph paths | DFS |
| Dependency ordering | Topological sort |
| Connectivity merging | DSU |
| All shortest paths | Floyd-Warshall |
| Non-negative weighted shortest path | Dijkstra |
| Negative edges | Bellman-Ford |
| Optimization with overlapping states | DP |
| Generate every possibility | Backtracking |
| Locally optimal choices with proof | Greedy |
| Prefix-based word search | Trie |
| Dynamic range query | Segment Tree/Fenwick Tree |

These are starting signals, not automatic rules. Always verify that the technique fits the constraints.

- Pattern

State:

```text
Time:
Space:
```

- Empty input
- One element
- Duplicate values
- Negative values
- Already sorted input
- Reverse-sorted input
- Maximum input size
- Repeated values
- Boundary indexes

- Special case
